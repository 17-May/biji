# 事件循环

## 浏览器的进程模型

### 何为进程

- 程序运行需要有自己专属的内存空间，可以把这块内存空间简单的理解为进程
- 每个程序必须要有最少一个进程，进程之间互相独立，互相通信需要双方同意
- 主要目的是为了（程序）隔离

### 何为线程

- 一个进程最少有一个线程，进程开启是会自动创建一个线程来运行代码，该线程为主线程
- 同一个进程可以有多个线程

## 浏览器有哪些进程和线程

- 浏览器是多进程多线程的应用程序
- 为了避免相互影响，为了减少连环崩溃的几率，浏览器启动时会启动多个进程

### 主要进程

1. 浏览器进程
   - 主要负责界面的展示、用户交互、子进程管理等等。浏览器进程会启动多个线程处理不同的任务
2. 网络进程
   - 负责加载网络资源。网络进程内部会启动多个线程来处理不同的网络任务
3. 渲染进程
   - 渲染进程启动后，会启动一个渲染主线程，主线程负责执行HTML、CSS、JS代码。
   - 默认情况下，浏览器会为每个标签页开启一个新的渲染进程，保证不同的标签页之间不不像影响

## 渲染主线程如何工作

1. 解析HTML
2. 解析CSS
3. 计算样式
4. 布局
5. 处理图层
6. 每秒把页面画60次
7. 执行全局JS代码
8. 执行事件处理函数
9. 执行计时器的回调函数
10. 。。。

1. 最开始时，主线程进入一个无限循环
2. 每次循环会检查消息队列是否有任务存在。如果有，就取出第一个任务执行，执行完一个后进入下一次循环；如果没有，则进入休眠状态
3. 其他所有线程（包括其他进程的线程）可以随时向消息队列添加任务。新任务会加到消息队列的末尾。在添加新任务时，如果主线程是休眠状态，则会将其唤醒以继续循环拿取任务
4. 整个过程称为**消息循环（事件循环）**

### 何为异步

- 代码执行过程中无法立即处理的任务
- 计时完成后需要执行的任务 -- setTimeout、setInteral
- 网络通信完成后需要执行的任务 -- XHR、Fetch
- 用户操作后需要执行的任务 -- addEventListener
- 如果渲染主主线程等待这些任务的时机达到，就会导致主线程长期处于【阻塞】的状态，从而导致浏览器【卡死】

#### 如何理解JS的异步

1. JS是一门单线程的语言，它运行在浏览器的渲染主线程中，而渲染主线程只有一个。
2. 渲染主线程需要渲染页面、执行JS、解析html、解析css等等工作，非常繁忙。
3. 如果使用同步的方式可能导致主线程产生阻塞，导致消息队列中的其他任务无法执行，白白浪费主线程时间，也会导致页面无法及时渲染，造成用户卡死现象。
4. 浏览器使用异步处理，是为了当计时器、网络、事件监听等任务发生时，先将这些任务让其他线程处理，其他线程执行完后会将事先传递的回调函数包装成任务，加入消息队列末尾，等待主线程调度执行。
5. 异步模式可以使主线程永不阻塞，最大限度的保护单线程的流畅运行。

### 任务优先级

- 任务没有优先级，在消息队列先进先出。消息队列有优先级

##### W3C最新解释

- 每个任务都有一个任务类型，同类型的任务必须在同一个队列，不同类型的任务可以分属不同的队列。在一次事件循环中，由浏览器自己根据实际情况从不同的队列中去取出任务执行
- 浏览器必须准备好一个微队列，微队列中的任务优先所有其他任务执行

##### chrome 实现

- 延时队列：存放计时器回调任务，优先级【中】
- 交互队列：用户操作后产生的事件处理任务，优先级【高】
- 微队列：需要最快执行的任务，优先级【最高】
  - 主要添加方式：**Promise**、**MutationObserver**

```JS
//添加函数到微队列
Promise.resolve().then(函数)
```

- **网络队列和延时队列看等待时间，时间短的先运行**

### 面试题

#### 阐述一下JS的事件循环

- 事件循环又叫消息循环，是浏览器渲染主线程的工作方式
- 在Chrome源码中，它开启了一个不会结束的for循环，每次循环从消息队列中取出第一个任务执行，而其他线程只需要在合适的时候将任务加入到队列末尾即可
- 过去把消息队列简单分为宏队列和微队列，这种说法目前已无法满足复杂的浏览器环境，取而代之的是一种更加灵活多变的处理方式
- 根据W3C的官方解释，每个任务有一个类型，同一类型的任务必须在同一队列，不同的任务可以属于不同的队列。不同任务队列有不同的优先级，在一次事件循环中，由浏览器自行决定取哪一个对断裂的任务。但浏览器必须要有一个微队列，微队列的任务一定具有最高的优先级。

#### JS中的计时器能够做到精确计时么？为什么？

- 计算机硬件没有原子钟，无法做到精确计时
- 操作系统的计时函数本身就有少量偏差，由于JS的计时器最终调用的是操作系统的函数，也就携带了这些偏差
- 按照W3C的标准，浏览器实现计时器时，如果嵌套层级超过5层，则会带有4毫秒的最少时间，计时时间少于4毫秒时又带来了偏差
- 受事件循环的影响，计时器的回调函数只能在主线程空闲时运行，又带来了偏差
