# 组件

### 无状态组件（函数式组件）

```js
function App() {
  return (
      <h1>我是无状态组件</h1>
      <h2 name={name}></h2>//接收参数，实现数据响应
  );
}
```

### 有状态组件（数据响应）

- 组件数据状态变化使用state
- 需要在constructor中调用super，传入prop

```js
class App extends React.Component {
  constructor(prop) {
    super(prop);
    this.state = {
      count: 0,
    };
  }
  componentDidMount() {
    setInterval(() => {
      const count = this.state.count;
      this.setState({
        count: count + 1,
      });
    }, 500);
  }
  render() {
    const { count } = this.state;
    return <h1>{count}</h1>;
  }
}
```

# 事件

- `()=>{this.handleClick()}`:不推荐，性能不好
- `this.handleClick.bind(this)`：推荐
- `方法=()=>{}`: public class fields语法，推荐。传参还是使用第一种

```js
<button onClick={this.handleClick.bind(this,'id')}>点击</button>
```

# props

外部组件传参，内部组件使用props接收

```js
class App extends React.Component {
  constructor(props) {
    super(props);
    this.name = props.name;
  }
  render() {
    const name = this.name;
    return (
      <>
        <h1>{name}</h1>
      </>
    );
  }
}
<App name="xxx" />
```

# setState和Props的区别

1. 只要setState就会执行当前组件的render方法，会执行两次（挂载和更新），其实不完全准确
2. props的组件，状态变化是由props的变化引起的，只要props不发生变化，组件就不会进行更新（有缓存）
3. 两个没有任何关联，只管自己

# Component中state和props的区别

- 组件内部可以形成闭环的状态，不管是静态还是动态，使用state
- 组件外部的状态，经常需要发生变化，或者定制化的内容，可以考虑使用props

# 生命周期（16.3之前和之后是两个版本）

- 每一次由状态改变导致页面视图的改变，都会经历：`render`阶段和`commit`阶段
- 只有class组件才有生命周期，class会创建对象实例，函数组件不会。组件实例从创建到销毁的过程被称生命周期
- `render`阶段找出需要修改的DOM，并存起来,`commit`阶段进行修改

### 为啥废弃三个钩子函数？有哪些问题？React如何解决？

##### 废弃

- componentWillMount、componentWillReceiveProps、componentWillUpdate都是在render阶段执行
- 在fiber架构被应用之前，render阶段是不能被打断的。当页面复杂之后，可能会阻塞页面渲染
- React推出fiber架构，低优先级任务的render阶段可以被高优先级任务打断

##### 问题

- 在render 阶段执行的生命周期函数可能被多次执行

##### 解决

- 新增getDerivedStateFromProps（静态方法）取代三个生命周期钩子

# 循环渲染key的作用

- 对组件进行一个标记，在render的时候可以复用，提升性能。
- key必须是唯一的，否则渲染结果出错
- 不建议使用数组下标，渲染性能减低

# 组合

### 包含关系

- `props.children`、`props.left`、`props.right`
- 实际上是props的属性而已，children是默认值

```js
function Person(props) {
  return <div>{props.children}</div>;
}
root.render(
  <Person>
    <div>子节点</div>
  </Person>
);

function Person(props) {
  return (
    <div>
      <h1>{props.left}</h1>
      <h2>{props.right}</h2>
    </div>
  );
}
root.render(<Person left={<div>左</div>} right={<div>右</div>}></Person>);
```

# 组件设计思路

1. 将设计好的UI划分为组件层级
2. 用React创建一个静态版本
3. 确定UI state的最小（且完整）表示
   - 该数据是否是由父组件通过props传递而来？如果是，则不是state
   - 该数据是否随时间的推移而保持不变？如果是，则不是state
   - 你能否根据其他state和props计算出该数据的值？如果是，则不是state
4. 确定state放置的位置
   - 找到根据这个state进行渲染的所有组件
   - 找到他们的共同所有者组件
   - 该共同所有者组件或者比他层级更高的组件应该拥有该state
   - 如果你找不到一个合适的位置来存放该state,就可以直接创建一个新的组件来存放该state,并将这一新组件置于高于共同所有者组件层级的位置
5. 添加反向数据流

# PureComponent

- 把props所有的属性拿出来遍历，把state所有的属性拿出来遍历，只要属性的引用不一样，就更新组件否则不更新
- 原理：`shouldComponentUpdate`中进行判断
