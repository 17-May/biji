# 笔记本出售寄件前私有证据流程

> 目的：在不向买家公开核心硬件唯一信息的前提下，完成寄件前取证、固定证据内容，并保留快递交付节点证据。  
> 原则：**核心硬件数据只自己保存；买家只知道“已完成存证”，不拿到底层硬件唯一标识。**

---
## 从第二到第六全部视频完整拍一遍
+ 硬件信息全部提前截图，录像的时候全部过一遍软件

## 一、寄件前先做的事

### 1. 整理机器
- 清理个人数据。
- 确认系统能正常开机。
- 确认屏幕、键盘、触摸板、充电、接口等基本功能正常。
- 确认准备出售时的最终硬件状态，不再更换硬件。

### 2. 拍整机外观
用手机拍原图，不修图：

- A 面
- B 面
- C 面
- D 面
- 四角
- 接口
- 已有划痕、磕碰
- 机身背面整机 SN

机身背面的整机 SN 作为实体机器的物理身份锚点。

---

## 二、拍 BIOS 身份信息

进入 BIOS，拍照或录短视频即可。

重点拍：

- Serial Number
- System UUID
- Machine Type / Model
- BIOS Version

目的：

**将机身实体 SN 与 BIOS 内部身份对应起来。**

不需要长时间录像，拍清楚即可。

---

## 三、进入 Windows 做硬件检测

寄件当天重新检测一次，不只依赖以前的旧资料。

### 1. CPU-Z
- 打开 CPU-Z。
- 检查 CPU、主板、内存、SPD、显卡等信息。
- 导出当天的 HTML 原始报告。

建议文件名：

```text
CPU-Z_寄件前.html
```

### 2. AIDA64
- 打开 AIDA64。
- 查看整机、主板、BIOS、内存 SPD、存储设备、显卡、网卡等信息。
- 导出当天的原始报告。

建议文件名：

```text
AIDA64_寄件前.html
```

AIDA64 的作用是作为第二套综合硬件检测来源，与 CPU-Z 互相印证。

### 3. SSD 检测
使用 CrystalDiskInfo 或其他可靠磁盘信息工具。

保存一张清晰截图或原始报告。

建议文件名：

```text
SSD_寄件前.png
```

### 4. 其他必要截图
如有需要，可另外保存：

```text
内存SPD_寄件前.png
主板信息_寄件前.png
显卡信息_寄件前.png
网卡信息_寄件前.png
BIOS_寄件前.jpg
```

---

## 四、建立“寄件前私有证据包”

建立一个文件夹，例如：

```text
笔记本发货证据_20260913
```

里面放：

```text
01_订单及商品信息
02_整机外观照片
03_机身SN照片
04_BIOS照片或视频
05_CPU-Z_寄件前.html
06_AIDA64_寄件前.html
07_SSD_寄件前.png
08_内存SPD_寄件前.png
09_其他核心硬件截图
10_网卡信息.png
11_说明.txt
```

这些资料只自己保存，不主动发送给买家。

---

## 五、压缩整个证据包

将整个文件夹压缩为一个 ZIP。

例如：

```text
笔记本发货私有证据_20260913.zip
```

注意：

- ZIP 生成后不要再修改内部内容。
- 原始照片、报告、视频保留原件。
- 不要用后期编辑过的文件替换原始文件。

---

## 六、计算整个 ZIP 的 SHA-256

在 PowerShell 中运行：

```powershell
Get-FileHash ".\笔记本发货私有证据_20260913.zip" -Algorithm SHA256
```

得到的 SHA-256 是根据 ZIP 文件全部二进制内容计算出来的。

只要 ZIP 内容任何一个字节发生变化，SHA-256 就会变化。

### 建议同时生成 TXT

```powershell
Get-FileHash ".\笔记本发货私有证据_20260913.zip" -Algorithm SHA256 |
Format-List |
Out-File ".\笔记本发货私有证据_20260913_SHA256.txt"
```

---

## 七、做寄件前时间留痕

SHA-256 只能证明文件内容是否变化，不能单独证明它是什么时候生成的。

所以寄件前要把以下内容保存到有第三方时间记录的位置：

```text
证据包文件名
SHA-256
日期
```

可以选择：

- 自己的邮箱
- 有历史版本的云盘
- 云端笔记
- 正规电子存证服务

核心硬件原始数据不需要公开给买家。

---

## 八、争议发生后的举证材料

可以给买家一张简单图片，只写：

```text
本机已于发货前完成整机及核心硬件检测并私有留档。

已完成：
- 整机身份核验
- BIOS / UUID 核验
- CPU / 主板 / 内存 / SSD / 显卡检测
- 原始 CPU-Z 报告
- 原始 AIDA64 报告
- SSD 信息留档
- 设备状态留档

证据包 SHA-256：
XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

核心硬件唯一标识及完整原始报告由卖方私有保存，
不向交易对方公开。
如发生硬件、配置或退货争议，可向平台或相关处理方提交原始证据核验。
```

### 不向买家公开

不要主动给买家：

- System UUID
- 主板 SN
- SSD SN
- 内存 SN
- 网卡 MAC
- 完整 CPU-Z 原始报告
- 完整 AIDA64 原始报告
- 私有证据 ZIP

买家只需要知道：

**发货前已经完成完整存证。**

---

## 九、正常包装

不要求“硬件检测完成后一直连续录像到封箱”。

现实做法：

- 完成取证后正常关机。
- 正常整理机器。
- 正常包装。

如条件允许，可以使用带唯一编号的一次性防拆贴。

---

## 十、包装完成后拍照

自己至少拍：

- 完整包裹
- 封口状态
- 快递面单
- 运单号
- 防拆贴编号（如果使用）

这一步证明寄出时的包装状态。

---

## 十一、快递取件

让快递员按快递公司的正常流程拍取件照片即可。

如果条件允许，让取件照片尽量包含：

- 完整包裹
- 面单
- 运单号
- 封口
- 防拆贴编号

快递员不需要知道内部硬件数据。

快递照片的作用是证明：

**这个包装状态的包裹在该时间点进入快递物流体系。**

---

## 十二、保存快递证据

保存：

- 运单号
- 揽收时间
- 快递员取件照片（如能获取）
- 物流轨迹
- 包裹重量（如有）
- 快递面单照片

包裹重量属于很有用的辅助证据。

---

## 十三、如果发生退货

收到退货后，不要先拆。

按以下顺序：

1. 手机开始录像。
2. 拍完整外箱。
3. 拍运单。
4. 拍封口和防拆贴。
5. 连续拆箱。
6. 拍整机外观。
7. 拍机身背面整机 SN。
8. 开机。
9. 进入 BIOS。
10. 再运行 CPU-Z。
11. 再运行 AIDA64。
12. 再检查 SSD。
13. 将退回后的信息与寄件前私有证据包进行比对。

如发生争议，再向平台或相关处理方提交：

- 寄件前原始证据 ZIP
- 原始 SHA-256
- 寄件前时间留痕
- 寄件照片
- 快递记录
- 退回后连续开箱及检测视频

---

## 十四、日常执行精简版

每次出售笔记本，只需要按下面做：

```text
1. 拍整机外观和背面 SN
2. 拍 BIOS
3. 运行 CPU-Z 并导出 HTML
4. 运行 AIDA64 并导出报告
5. 检查 SSD 并保存截图/报告
6. 保存必要的内存、显卡、网卡截图
7. 所有原始材料放入同一文件夹
8. 压缩为 ZIP
9. 对 ZIP 计算 SHA-256
10. 对 SHA-256 做寄件前时间留痕
11. 给买家一张不泄露核心硬件数据的“已完成私有存证”凭证
12. 正常包装
13. 自己拍包裹、面单、封口
14. 让快递员按工作流程拍取件照片
15. 保存运单、揽收时间、物流轨迹、重量
```

---

## 核心原则

> **私有技术证据负责证明“这台机器寄出前内部是什么”。**  
> **整机 SN 负责把技术证据绑定到具体实体机器。**  
> **SHA-256 负责固定证据包内容。**  
> **第三方时间记录负责证明该哈希在寄件前已经存在。**  
> **快递照片、运单和重量负责证明包裹进入物流体系时的状态。**

这套流程的目标不是保证任何争议都绝对不会发生，而是让发生争议时，你能够拿出一套前后可核验、时间明确、内容固定的完整证据链。
